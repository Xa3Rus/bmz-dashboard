# Спецификация архитектуры: Таск-мессенджер УАиБД БМЗ

## 1. Назначение и контекст системы
Программный комплекс **«Таск-мессенджер УАиБД»** представляет собой десктопное приложение для оперативного управления задачами и инженерной коммуникации сотрудников Управления автоматизации и баз данных (УАиБД) Белорусского металлургического завода (БМЗ).

Система закрывает две ключевые потребности отдела:
1. **Координация и контроль задач**: выдача технических заданий ведущим инженером или начальником отдела программистам АСУ ТП, отслеживание стадий выполнения, прикрепление отчетов с технической документацией, логами и дампами с печей ДСП, согласование или возврат на доработку.
2. **Мгновенный обмен сообщениями в стиле Discord**: общий канал для объявлений и оперативных сводок цеха, персональные диалоги между программистами и руководством с поддержкой форматирования кода, логов и передачи производственных файлов.

## 2. Архитектура и стек технологий

```
+-------------------------------------------------------------+
|              Electron Desktop Client (Windows)              |
|                                                             |
|  +-------------------------------------------------------+  |
|  |                 Renderer (HTML5 / CSS3 / JS)          |  |
|  |   - Discord-подобная 3-колоночная компоновка          |  |
|  |   - Вкладки переключения: [ Чат ] / [ Задачи ]        |  |
|  |   - Управление задачами и форма сдачи отчетов         |  |
|  +-------------------------------------------------------+  |
|                             ▲                               |
|                             │ contextBridge (preload.js)    |
|                             ▼                               |
|  +-------------------------------------------------------+  |
|  |                 Electron Main Process                 |  |
|  |   - Управление окном, системные уведомления ОС        |  |
|  |   - Чтение config.json (URL и ключ Supabase)          |  |
|  +-------------------------------------------------------+  |
+------------------------------▲------------------------------+
                               │ HTTPS / WSS (Realtime)
                               ▼
+-------------------------------------------------------------+
|                       Supabase Cloud                        |
|                                                             |
|  +-------------------+  +-------------------+  +----------+ |
|  |    PostgreSQL     |  |     Realtime      |  | Storage  | |
|  | (Profiles, Tasks, |  |  (WebSockets для  |  |  (Бакет  | |
|  |  Messages, Chats) |  |   чата и тасок)   |  | uaibd)   | |
|  +-------------------+  +-------------------+  +----------+ |
+-------------------------------------------------------------+
```

* **Платформа клиента**: Electron (Node.js runtime + Chromium) для развертывания на рабочих местах инженеров и руководства.
* **Сетевой уровень и БД**: Supabase (PostgreSQL 15+).
* **Синхронизация в реальном времени**: Supabase Realtime (WebSocket-подписки на события `INSERT` и `UPDATE` в таблицах сообщений и задач).
* **Хранилище артефактов**: Supabase Storage (бакет `uaibd-files` для отчетов, файлов логов, скриншотов).
* **Конфигурация**: параметры подключения (`SUPABASE_URL`, `SUPABASE_ANON_KEY`) считываются из защищенного конфигурационного файла (`config.json`), исключая необходимость ручной настройки в UI.

## 3. Модель данных (Схема PostgreSQL)

### 3.1. Таблица `profiles` (Профили пользователей)
```sql
CREATE TABLE profiles (
    id UUID PRIMARY KEY REFERENCES auth.users(id) ON DELETE CASCADE,
    email TEXT NOT NULL UNIQUE,
    full_name TEXT NOT NULL,
    role TEXT NOT NULL CHECK (role IN ('chief', 'lead_engineer', 'developer')),
    status_text TEXT DEFAULT 'На смене',
    avatar_color TEXT DEFAULT '#4f545c',
    is_online BOOLEAN DEFAULT false,
    last_seen TIMESTAMPTZ DEFAULT NOW(),
    created_at TIMESTAMPTZ DEFAULT NOW()
);
```

### 3.2. Таблица `channels` (Каналы общего доступа)
```sql
CREATE TABLE channels (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    slug TEXT NOT NULL UNIQUE,
    name TEXT NOT NULL,
    topic TEXT,
    created_at TIMESTAMPTZ DEFAULT NOW()
);
-- По умолчанию создается базовый общий канал
INSERT INTO channels (slug, name, topic) 
VALUES ('general', 'общий-чат', 'Оперативная координация дежурных смен и объявления УАиБД');
```

### 3.3. Таблица `direct_chats` (Личные диалоги)
```sql
CREATE TABLE direct_chats (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_1 UUID NOT NULL REFERENCES profiles(id) ON DELETE CASCADE,
    user_2 UUID NOT NULL REFERENCES profiles(id) ON DELETE CASCADE,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    CONSTRAINT unique_user_pair UNIQUE (user_1, user_2)
);
```

### 3.4. Таблица `messages` (Сообщения)
```sql
CREATE TABLE messages (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    channel_id UUID REFERENCES channels(id) ON DELETE CASCADE,
    direct_chat_id UUID REFERENCES direct_chats(id) ON DELETE CASCADE,
    sender_id UUID NOT NULL REFERENCES profiles(id) ON DELETE CASCADE,
    content TEXT NOT NULL,
    attachments JSONB DEFAULT '[]'::jsonb, -- [{ name, size, type, url }]
    created_at TIMESTAMPTZ DEFAULT NOW(),
    CONSTRAINT msg_target_check CHECK (
        (channel_id IS NOT NULL AND direct_chat_id IS NULL) OR
        (channel_id IS NULL AND direct_chat_id IS NOT NULL)
    )
);
```

### 3.5. Таблица `tasks` (Задачи)
```sql
CREATE TABLE tasks (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    title TEXT NOT NULL,
    description TEXT NOT NULL,
    creator_id UUID NOT NULL REFERENCES profiles(id) ON DELETE RESTRICT,
    assignee_id UUID NOT NULL REFERENCES profiles(id) ON DELETE RESTRICT,
    priority TEXT NOT NULL CHECK (priority IN ('urgent', 'high', 'normal')),
    status TEXT NOT NULL CHECK (status IN ('todo', 'in_progress', 'review', 'done')) DEFAULT 'todo',
    due_date DATE,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);
```

### 3.6. Таблица `task_reports` (Отчеты программистов по задачам)
```sql
CREATE TABLE task_reports (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    task_id UUID NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
    author_id UUID NOT NULL REFERENCES profiles(id) ON DELETE CASCADE,
    report_text TEXT NOT NULL,
    attachments JSONB DEFAULT '[]'::jsonb, -- [{ name, size, type, url }]
    review_comment TEXT,
    created_at TIMESTAMPTZ DEFAULT NOW()
);
```

## 4. Ролевая модель и жизненный цикл задач

### 4.1. Разграничение прав доступа
| Действие | Начальник УАиБД (`chief`) | Ведущий инженер (`lead_engineer`) | Программист (`developer`) |
|---|:---:|:---:|:---:|
| Просмотр общего чата `#общий-чат` | Да | Да | Да |
| Создание / назначение задач | Да | Да | Нет |
| Перевод задачи в статус «В работе» | Нет (для себя) | Нет (для себя) | Да |
| Сдача отчета с прикреплением файлов | Нет | Нет | Да |
| Согласование отчета («Принято») | Да | Да | Нет |
| Возврат задачи на доработку с замечанием | Да | Да | Нет |
| Личные диалоги с коллегами | Да | Да | Да |

### 4.2. Жизненный цикл задачи (Диаграмма переходов)
```
[Ведущий инженер / Начальник] 
     │  Создание задачи: Название, Описание, Исполнитель, Приоритет, Дедлайн
     ▼
┌──────────────┐
│     TODO     │ ◄─────────────────────────────────────────────┐
│ (Назначена)  │                                               │
└──────┬───────┘                                               │
       │                                                       │
       │ Программист нажимает «Взять в работу»                 │
       ▼                                                       │
┌──────────────┐                                               │
│ IN_PROGRESS  │                                               │
│  (В работе)  │                                               │
└──────┬───────┘                                               │
       │                                                       │
       │ Программист заполняет отчет + файлы (логи/документы)   │
       ▼                                                       │
┌──────────────┐                                               │
│    REVIEW    │                                               │
│ (На проверке)│                                               │
└──────┬───────┴───────────────────────────────────────────────┘
       │                                          ▲
       │ Начальник/Вед. инженер                   │ «На доработку»
       │ нажимает «Принять отчет»                 │ (с комментарием)
       ▼                                          │
┌──────────────┐                                  │
│     DONE     │                                  │
│  (Выполнено) │                                  │
└──────────────┘                                  │
```

## 5. Архитектура пользовательского интерфейса (Discord Dark Style)

### 5.1. Трехколоночная компоновка
1. **Левая сервисная панель (`Navigation Bar`)**:
   * Логотип предприятия БМЗ и отдела УАиБД.
   * Разделитель.
   * Кнопка прямого перехода в Общий чат.
   * Индикатор текущего пользователя внизу: статусная точка (Online/Offline), имя, роль (`[Начальник]`, `[Вед. инж]`, `[Программист]`), кнопка выхода.

2. **Вторая колонка (`Channels & Contacts Sidebar`)**:
   * **Каналы**:
     * `# общий-чат` (с индикатором новых сообщений).
   * **Сотрудники (Личные диалоги)**:
     * Раздел «Руководство» (`chief`, `lead_engineer`).
     * Раздел «Разработка и АСУ ТП» (`developer`).
     * Отображение аватара, статуса активности в сети и счетчика назначенных задач.

3. **Центральная рабочая зона (`Main Chat & Tasks Stage`)**:
   * **Шапка**:
     * Заголовок (Имя собеседника или `# общий-чат`).
     * Статусный текст («В сети», «На смене ДСП-1»).
     * **Таб-селектор режима (для личных диалогов)**:
       * `💬 Чат`: экран переписки в реальном времени.
       * `📋 Задачи [N]`: экран управления задачами с бейджем количества активных тасок.
   * **Режим «Чат»**:
     * Поток сообщений с группировкой по авторам и времени.
     * Карточки прикрепленных файлов: иконка расширения (`.txt`, `.pdf`, `.docx`, `.png`), размер файла, кнопка скачивания.
     * Блок ввода сообщения: многострочное поле, кнопка прикрепления файлов (скрепка), поддержка отправки по Enter (Shift+Enter для новой строки).
   * **Режим «Задачи»**:
     * Верхняя плашка действий: кнопка `+ Назначить задачу` (для руководителя).
     * Фильтр по статусам: Все / К выполнению / В работе / На проверке / Выполнено.
     * Карточка задачи:
       * Бейдж приоритета (Красный — Срочно/Авария, Оранжевый — Высокий, Серый — Плановый).
       * Заголовок и подробное техническое описание.
       * Срок сдачи (дедлайн).
       * Блок прикрепленных отчетов: текст решения программиста, ссылки на прикрепленные файлы.
       * Кнопки действий:
         * Для программиста: «Взять в работу», «Сдать отчет».
         * Для руководителя: «Принять работу», «Вернуть на доработку» (модальное окно с вводом замечаний).

4. **Форма сдачи отчета (Модальное окно)**:
   * Поле подробного описания выполненной работы (какие регистры ПЛК изменены, алгоритм исправлен, результат тестирования).
   * Область загрузки файлов: отчеты `.docx`/`.pdf`, дампы `.txt`, архивы конфигураций.
   * Кнопка отправки на проверку.

## 6. Обработка ошибок и отказоустойчивость

* **Потеря сетевого соединения**: перехват событий сброса WebSocket в `supabase-js`, отображение уведомления «Связь с сервером прервана. Автоматическое переподключение...». При восстановлении соединения подписки возобновляются без потери контекста.
* **Защита от сбоя отправки файлов**: валидация размера файлов (до 50 МБ на файл) перед отправкой в Storage. Отображение прогресс-бара загрузки.
* **Безопасность сессии**: токен сессии Supabase сохраняется в локальном защищенном хранилище приложения, повторная авторизация при перезапуске приложения не требуется.

## 7. План размещения файлов проекта

Все компоненты изолированы в отдельной директории `uaibd-messenger/`:
```
uaibd-messenger/
├── package.json
├── main.js                 # Главный процесс Electron
├── preload.js              # Изолированный безопасный IPC-мост
├── config.json             # Конфигурация Supabase URL и Anon Key
├── schema.sql              # Полный SQL DDL для инициализации базы данных
└── renderer/
    ├── index.html          # Разметка Discord-интерфейса
    ├── style.css           # Тёмная тема в индустриальном стиле
    ├── app.js              # Контроллер интерфейса и бизнес-логика
    ├── supabaseClient.js   # Инициализация Supabase и Realtime подписок
    └── assets/             # Иконки и логотипы
```
