# UA&BD Task Messenger — Корпоративный таск-мессенджер УАиБД ОАО «БМЗ»

Настольное приложение оперативной диспетчеризации технических задач, координации инженерных смен и обмена технологическими отчетами для сотрудников **Управления автоматизации и баз данных (УАиБД)** ОАО «Белорусский металлургический завод».

Приложение разработано в стиле **Discord Dark Industrial** с заводской акцентной палитрой БМЗ и предназначено для эксплуатации на автоматизированных рабочих местах (АРМ) инженеров АСУ ТП, системных программистов и руководства управления.

---

## 1. Назначение и функциональные возможности

В условиях непрерывного металлургического производства (электросталеплавильные, сортопрокатные и трубопрокатные цеха) использование публичных мессенджеров (Telegram, WhatsApp) недопустимо по требованиям промышленной безопасности и политики защиты критической информационной инфраструктуры (КИИ).

**UA&BD Task Messenger решает ключевые производственные задачи:**
- **Оперативная коммуникация дежурного персонала**: тематический канал `#общий-чат` для передачи смен и обсуждения аварийных инцидентов, а также личные диалоги между сотрудниками.
- **Строгий контроль производственных заданий**: назначение задач по наладке ПЛК, калибровке датчиков и оптимизации баз данных с контролем дедлайнов и приоритетов.
- **Инженерная отчетность**: обязательное предоставление текстового отчета и прикрепление подтверждающих файлов (дампы памяти ПЛК, диагностические журналы `.txt`/`.log`, схемы, скриншоты SCADA) перед передачей задачи на проверку.
- **Двухэтапная приемка работ**: руководитель или ведущий инженер проверяет отчет и принимает задачу либо возвращает её исполнителю с мотивированным комментарием.
- **Мгновенная синхронизация (Realtime)**: поступление сообщений, обновление статусов задач и уведомления происходят в реальном времени по протоколу WebSocket без необходимости ручного обновления страницы.

- **Платформа**: Electron 34+ (Node.js 18+).

- **Интерфейс**: Нативный HTML5/CSS3/JavaScript (ES6+) без тяжелых зависимостей. Трехколоночная верстка в индустриальном стиле Discord.
- **СУБД и Backend**: PostgreSQL 15+ через сервис Supabase (или собственный Self-Hosted контур на сервере предприятия).
- **Сетевой протокол**: HTTPS для REST API и WSS (WebSocket Secure) для событий Realtime.

## 3. Ролевая модель (RBAC) и жизненный цикл задач

В системе строго реализовано разграничение доступа по служебным ролям сотрудников УАиБД:

| Роль | Идентификатор | Назначение задач | Взятие задачи в работу | Сдача отчета с файлами | Проверка и приемка отчетов | Общий и личный чат |
| :--- | :---: | :---: | :---: | :---: | :---: | :---: |
| **Начальник УАиБД** | `chief` | Да | Да | Да | **Да (Принять / На доработку)** | Да |
| **Ведущий инженер** | `lead_engineer` | Да | Да | Да | **Да (Принять / На доработку)** | Да |
| **Программист** | `developer` | **Нет** | Да | Да | **Нет** | Да |

### Жизненный цикл задачи (Task State Machine)

```text
 ┌─────────┐      Назначение задачи       ┌───────────────┐
 │  TODO   │ ───────────────────────────► │  IN_PROGRESS  │
 │К исполн.│   (Программист берет задачу) │   В работе    │
 └─────────┘                              └───────┬───────┘
                                                  │
                                                  │ Сдача отчета с файлом дампа
                                                  ▼
 ┌─────────┐       Резолюция: Принять     ┌───────────────┐
 │  DONE   │ ◄─────────────────────────── │    REVIEW     │
 │Выполнено│     (Начальник / Вед. инж.)  │  На проверке  │
 └─────────┘                              └───────┬───────┘
      ▲                                           │
      │        Резолюция: Вернуть на доработку    │
      └───────────────────────────────────────────┘
```

1. **`todo` (К выполнению)**: Задача создана руководителем или ведущим инженером. Назначен конкретный исполнитель, срок и приоритет (`urgent`, `high`, `normal`).
2. **`in_progress` (В работе)**: Назначенный программист нажимает кнопку «Взять в работу». Задача переходит в активную фазу.
3. **`review` (На проверке)**: Программист заполняет форму инженерного отчета, прикрепляет файлы дампов/логов и отправляет на проверку.
4. **`done` (Выполнено)**: Руководитель изучает отчет и принимает задачу. При наличии замечаний задача возвращается со статусом «На доработку» и комментарием руководителя.

## 4. Быстрый старт и установка

### Системные требования
- Операционная система: Windows 10/11 (или Windows Server 2016+).
- Node.js версии `18.0.0` или выше.
- Пакетный менеджер `npm` версии `9.x` или выше.

### Шаг 1. Клонирование и установка зависимостей

```bash
# Переход в каталог мессенджера
cd uaibd-messenger

# Установка зависимостей (Electron, @supabase/supabase-js)
npm install
```

### Шаг 2. Настройка подключения к базе данных (Supabase)

Приложение может работать как с реальной облачной/корпоративной базой данных Supabase, так и в автономном **демо-режиме** на встроенных данных.

Для подключения к вашей базе данных:
1. Зарегистрируйтесь на [supabase.com](https://supabase.com) (или разверните локальный инстанс Supabase через Docker).
2. Создайте новый проект (например, `bmz-uaibd-messenger`).
3. Скопируйте **Project URL** и **API Anon Key** из раздела `Project Settings -> API`.
4. Откройте файл `uaibd-messenger/config.json` и укажите ваши параметры:

```json
{
  "supabaseUrl": "https://your-project-id.supabase.co",
  "supabaseAnonKey": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}
```

### Шаг 3. Инициализация схемы базы данных (за 3 минуты)

1. В панели управления Supabase перейдите в раздел **SQL Editor**.
2. Нажмите **New query**.
3. Скопируйте содержимое файла `uaibd-messenger/schema.sql` и вставьте его в окно редактора.
4. Нажмите кнопку **Run**.

Скрипт автоматически создаст:
- Таблицы `profiles`, `channels`, `direct_chats`, `messages`, `tasks`, `task_reports`.
- Необходимые B-Tree индексы для мгновенного выполнения запросов.
- Триггер автоматического обновления временной метки `updated_at`.
- Политики Row Level Security (RLS) для защиты данных.
- Хранилище файлов (Storage Bucket) `uaibd-files` для инженерных дампов и логов.
- Стартовые учетные записи сотрудников УАиБД и демонстрационные задачи.

### Шаг 4. Запуск приложения

```bash
npm start
```

Окно приложения откроется с разрешением 1280x800 в темной промышленной теме.

В проекте реализован полный набор автоматических тестов с использованием встроенного тест-раннера Node.js (`node:test`). Тесты не требуют внешних фреймворков и выполняются мгновенно.

Успешный вывод тестов подтверждает целостность всех компонентов:

- Безопасность контекста Electron и Preload.
- Рендеринг интерфейса и форматирование файлов.

## 7. Руководство пользователя по интерфейсу

### Колонка 1. Навигация по серверу (Server Bar)
- **Иконка БМЗ УАиБД**: логотип подразделения завода.
- **Иконка «Общий отдел» (🏭)**: быстрый переход к рабочей области отдела.
- **Иконка «Сводка задач» (📊)**: оперативный переключатель на список задач.
- **Индикатор статуса сети**: зелёная точка подтверждает активное WebSocket-соединение с сервером.

### Колонка 2. Каналы, сотрудники и текущий профиль
- **Текстовые каналы**: выбор канала `#общий-чат` с бейджем непрочитанных сообщений.
- **Категория «Руководство»**: список начальников и ведущих инженеров со статусом присутствия («В сети») и счетчиком активных задач.
- **Категория «Разработка и АСУ ТП»**: список программистов отдела.
- **Панель текущего пользователя (внизу)**: отображает ФИО текущего сотрудника и бейдж роли. Кнопка **🔄 («Сменить профиль»)** позволяет мгновенно переключиться между учетными записями для демонстрации и проверки прав доступа.

### Колонка 3. Основная рабочая область
- **Вкладка «Чат»**:
  - Лента сообщений с группировкой по датам.
  - Поддержка форматирования Markdown и подсветки блоков программного кода (регистры ПЛК, SQL-запросы).
  - Карточки прикрепленных файлов с иконками типов (`.txt`, `.log`, `.pdf`, `.docx`, изображения).
  - Поле ввода сообщения с поддержкой отправки по `Enter` (перенос строки — `Shift+Enter`) и кнопкой прикрепления файлов.
- **Вкладка «Задачи»**:
  - Фильтры по статусам: «Все», «К выполнению», «В работе», «На проверке», «Выполнено».
  - Кнопка **«+ Назначить задачу»** (активна только для Начальника УАиБД и Ведущего инженера).
  - Карточки задач с бейджами приоритета («Авария / Срочно», «Высокий», «Обычный») и дедлайна.
  - Кнопки ролевых действий: «Взять в работу», «Сдать отчет», «Проверить отчет».
